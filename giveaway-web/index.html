      How winners are picked: shuffle the positions 0…n−1, taking step i from keccak256(random word, i), and keep the first winners. The contract's winnerIndices function does exactly this, and winnersFrom checks that the list matches the one fixed at creation.

        Why it's fair

        • The list is fixed in the same transaction that requests randomness. Nobody can add or remove a name after the draw starts.
        • The random number depends on a future block hash, so nobody, the organiser included, knows it in advance.
        • Verity proves the number on-chain, and the contract has no way to draw again.
        • Every giveaway is public, with its own link, so a re-run by the organiser would be visible to everyone.
